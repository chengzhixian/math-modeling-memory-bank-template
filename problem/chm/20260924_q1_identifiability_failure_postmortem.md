# Q1 可识别性错误复盘与永久防复发规则

日期：2026-09-24  
角色：chm  
适用范围：本项目所有数学模型、数据分析、代码、跨题接口与论文结论审查。

## 1. 事故摘要

第一问曾把附件 A 中 1M、60M、1B 三个离散实验组上的配比效应幅度，进一步解释为只由模型参数规模 \(N\) 决定的连续衰减律：

\[
L_k(N,\mathbf p)
=
a_k(N)+b_k(N)s_k(\mathbf p),
\]

并继续拟合

\[
\log b_k(N)
=
c_k-\eta\log(N/10^6).
\]

该计算在数值上可执行，代码也能稳定产生 \(\eta\)，但**附件 A 并不足以识别“纯 \(N\) 导致的连续配比尺度律”**。A4--A15 的配比表只有 17 维配比，Loss 表只有 13 个验证域 Loss；与每个配方实验对应的训练数据量 \(D\) 并未作为字段给出。真实实验规模只有 1M、60M、1B 三个离散组，且 1B 的配方支持集与 1M/60M 不同。

因此，原先的核心问题不是代码算错，而是：

> **把“可拟合的经验趋势”错误升级成“由数据识别出的结构规律”。**

这是 identifiability error（可识别性错误），严重程度高于一般实现错误。

## 2. 错误是怎样发生的

### 2.1 下游需求反向驱动上游模型

Q2 最终需要 \(N,D,Q,\mathbf p\) 统一关系，因此 Q1 曾倾向于主动提供一个可跨规模消费的 \(\eta\)。实际思维顺序变成：

\[
\text{下游需要什么}
\rightarrow
\text{上游构造什么}.
\]

正确顺序必须是：

\[
\boxed{
\text{题面要求}
\rightarrow
\text{实际字段}
\rightarrow
\text{可识别量}
\rightarrow
\text{候选模型}
\rightarrow
\text{下游接口}
}
\]

下游“希望有某个参数”永远不能成为该参数存在的证据。

### 2.2 把实验组标签误当作受控自变量

文件名中的 1M、60M、1B 很容易被直接视作 \(N\)。但“组标签不同”不等于“除 \(N\) 外其他条件全部受控”。

如果 \(D\)、训练过程、配方支持等没有被控制或观测，就不能把组间差异唯一归因于 \(N\)。

### 2.3 数值稳定造成错误安全感

三点可以拟合趋势；bootstrap 也可以给区间；代码可重复运行。这些都不能证明结构解释成立。

必须永久记住：

\[
\boxed{
\text{参数可估计}
\neq
\text{参数可识别}
}
\]

\[
\boxed{
\text{拟合稳定}
\neq
\text{科学解释成立}
}
\]

### 2.4 文献范式先于数据条件

Scaling-law 文献提供的是候选建模形式及其适用条件，不是“看到不同规模就自动拟合幂律”的许可。

任何文献模型必须先回答：

1. 本题是否有模型所需全部变量？
2. 单位是否一致？
3. 数据是否满足其训练/验证设计？
4. 是否存在未控制混杂？
5. 支持域是否一致？

只要核心条件不满足，就只能作为思想或候选模型，不得写成已验证主模型。

## 3. 为什么此前多轮审查没有发现

### 3.1 审查重点错位

此前很多检查是在问：

- Ridge 是否实现正确；
- index 是否对齐；
- Spearman 是否稳定；
- \(\eta\) 是否能 bootstrap；
- 接口是否一致；
- 输出能否复现。

这些是在检查：

> “给定模型成立后，代码有没有正确实现它？”

但没有先强制问：

> “这个模型有没有资格存在？”

因此出现了“代码正确实现了一个数据不能支持的科学解释”。

### 3.2 前提继承导致一致地错

一旦第一版把 \(b_k(N)\)、\(\eta\) 写进文档，后续代码、接口和审查都会围绕它进行。

之后的问题变成：

> \(\eta\) 算得对不对？

而不是：

> 为什么这里应该存在一个 \(\eta\)？

以后审查必须包含“从零重建”阶段，禁止只沿用当前方案前提。

### 3.3 没有把结论按证据等级分层

必须区分：

1. 描述性：数据中观察到什么；
2. 预测性：held-out 上能否预测；
3. 结构性：某个机制/变量是否决定结果；
4. 因果性：干预是否导致结果；
5. 外推性：支持域外是否仍成立。

Q1 的数据可以支持“排序跨实验组稳定”这一预测性结论，但不能自动升级成“配比效应按 \(N^{-\eta}\) 衰减”的结构性规律。

### 3.4 support shift 没被当成识别阻断条件

1M 与 60M 使用同一批 256 个配方，适合直接比较；1B 使用另一批 64 个配方。若支持集改变，则观察到的幅度变化至少可能来自：

\[
\text{规模变化}
\quad\text{或}\quad
\text{配方分布变化}.
\]

数据无法排除替代解释时，结构结论必须降级。

## 4. 本次修复

Q1 已撤出连续跨规模幅度模型和公共 \(\eta\)。当前只保留附件 A 能直接支持的内容：

\[
Q_A
\]

作为 A 侧综合质量代理；

\[
\widehat L_{k,1M}(\mathbf p)
=
\widehat\alpha_k+
\widehat{\boldsymbol\beta}_k^\top
(\mathbf p-\mathbf p_{\rm ref})
\]

作为 13 个目标域独立的 1M 配比代理；

\[
\mathbf m(\mathbf p)
=
\mathbf B(\mathbf p-\mathbf p_{\rm ref})
\]

作为 13 维相对配比效应；

A6--A11 仅作为冻结模型的 held-out 排序验证；A12--A15 只作为 estimated/extrapolated 压力测试。

## 5. 永久防复发规则

以后任何新模型、公式、参数、机制解释，在进入代码或论文之前，必须回答以下问题。

### Gate A：变量来源

每个公式符号都必须登记：

| 项目 | 必填内容 |
|---|---|
| 符号 | 数学记号 |
| 数据来源 | 附件/文件/字段 |
| 单位 | 明确单位 |
| 类型 | observed / derived / assumed / scenario / latent |
| 数据角色 | train / validation / test / extrapolated |
| 支持域 | 取值范围和样本支持 |
| 是否可直接识别 | yes / no / conditional |

**任何核心变量无法指向题目字段或明确推导来源时，禁止把它写成“数据识别参数”。**

### Gate B：可识别性

拟合之前先问：

1. 同一观测现象是否存在其他合理解释？
2. 核心自变量是否与其他条件共同变化？
3. 是否只有极少离散点却声称连续规律？
4. 不同组的支持集是否一致？
5. 是否有变量缺失导致结构参数混杂？
6. 如果把标签换成“实验组 A/B/C”，模型结论是否仍成立？若成立，说明当前最多是组间经验关系，而非机制解释。

只要无法排除关键替代解释，结论必须降级。

### Gate C：数据角色冻结

建模前先冻结：

- training：允许拟合参数；
- tuning/CV：允许模型选择；
- validation/test：只允许一次性外部检验；
- estimated/extrapolated：只允许压力测试或情景分析。

禁止验证集在验证后又回流拟合核心参数，却继续被称为外部验证。

### Gate D：证据等级

每条论文结论必须标注其等级：

- D1 描述性；
- D2 预测性；
- D3 结构性；
- D4 因果性；
- D5 外推性。

审查者必须确认“证据等级 >= 结论等级”，否则降级措辞或撤回。

## 6. 强制完整审查流程

以后只要用户或成员提出以下任一请求：

- “审查一下远程仓库/我的分支”
- “审查代码”
- “审查数学模型”
- “审查问题有没有问题”
- “检查本地仓库”
- “重新 review 一遍”
- “看看模型是否严谨”
- “检查结果能不能写进论文”

无论对象是远程分支还是本地工作区，都必须执行公共文件 REPOSITORY_REVIEW_PROTOCOL.md 定义的完整流程，不能只做代码 lint、diff 或数值复算。

审查至少必须包含：

1. 题面与可信来源核验；
2. requirement → data 映射；
3. variable provenance 表；
4. identifiability 审查；
5. train/validation/test/extrapolated 角色冻结；
6. overlap / leakage / support shift；
7. 文献模型适用条件；
8. 数学公式 ↔ 代码一致性；
9. 单位、索引、缺失值、非有限值与约束；
10. baseline / ablation / sensitivity；
11. held-out 与外推验证；
12. claim ladder；
13. 跨附件/跨问题接口；
14. 可复现性与哈希；
15. 从零 red-team 审查；
16. 分支 diff / 冲突 / legacy 清理；
17. blocker / major / minor 分级与最终可发布判断。

## 7. 审查时必须主动提出的反事实问题

每个核心公式都至少问一次：

- 如果没有当前这个公式，我仅看数据会自然得到它吗？
- 有没有另一种变量变化也能解释同一现象？
- 这个参数是真正被识别，还是仅仅能被优化器算出来？
- 验证数据有没有参与参数选择？
- 外推/半合成数据有没有被当成真实独立实验？
- 不同实验组是否使用相同支持集？
- 同名字段跨附件是否真是同一坐标？
- 如果删掉最复杂部分，简单 baseline 是否已经解释了大部分结果？
- 结论是否超出了数据支持范围？

## 8. 团队级原则

以后本项目任何 AI 都不得以“公式完整”“文献常用”“结果平滑”“bootstrap 区间窄”“代码测试通过”作为跳过可识别性审查的理由。

最高原则固定为：

\[
\boxed{
\text{先证明一个量能够从数据中识别，再允许给它写估计公式。}
\]

如果数据不能识别，正确结论就是“无法识别”，而不是为了四问衔接去补造参数。
