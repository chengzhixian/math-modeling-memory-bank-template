# 协作与研究约定

## 信息与证据

区分已验证事实、待验证假设和备选设想。公式与结论必须可追溯到题面、正式文献或实验；不得把 AI 输出作为学术依据。方法选型、核心推导和论证由团队完成并核验，记录 AI 实际辅助环节供论文披露。

## 数据与接口

- 原始文件只读；处理代码与生成结果分开。保留数据来源、可信度、单位、缺失规则、筛选口径与校验值。
- 实测、估算、半合成数据分别标注；训练、检验与外推边界在选模型前确定，避免泄漏。
- Q1 → Q2：输出质量评分、域映射、配比及其效应和不确定性；Q2 不重读附件 A 原始记录。
- Q2 → Q3：输出模型形式、参数、尺度、适用范围及参数不确定性；Q3 同时记录约束残差和可行性。
- Q1–Q3 → Q4：通过经验证的 Loss–Benchmark 映射连接，不把 Loss 改善直接等同于能力提升。
- 每个实验记录编号、输入版本、参数、随机种子、命令、耗时、输出、验证方式和局限。
- 论文关键数值与图表建立索引，指向对应代码、输入及实验记录。

## 排期纪律

每天 12:00、18:00 与 21:30 建议做团队短检查和集成，关键交接点即时处理；不自动创建提醒。模型工作与论文同步推进。25 日 23:00 前必须有四问完整初稿；26 日 15:00 后仅为错误或必要补证修改核心模型。落后时优先保留全部题面必做项，削减附加模型与装饰性实验。

## 三人写入隔离与记忆汇总

权威流程见 TEAM_WORKFLOW.md。三台电脑各自 clone；个人分支只有本人写入，main 由唯一集成人维护。A/B/C 分别拥有 src、outputs、experiments、problem、interfaces 下对应小写子目录和各自论文章节。修改他人范围前先协调，不依赖 Git 自动阻止。

普通成员只改 memory-bank/members/本人角色.md，并在 handoffs/本人角色/ 新增不可覆盖的交接。六个公共文件由集成人验收后汇总。个人分支推送后队友 fetch/git show 可读；正式输入默认采用已集成版本，临时输入须记录精确 SHA 与未集成状态。已备份、已验收和已集成是三种不同状态。

接口先定义字段、单位、版本、有效范围和证据；生产者修改自己接口，消费者记录所用版本。破坏性变更发新版本并标明重跑范围，禁止静默换数据、覆盖旧结果。分支合并逐个进行，固定个人分支保留 merge 历史，不强推。

## 额度耗尽前远程同步

此为用户明确的持续要求。每次有变更的任务结束、里程碑完成和长任务启动前都做检查点。工具可用时检查相关额度窗口；任一窗口剩余 ≤20% 优先保存和推送，≤10% 暂停新重任务直到完成远端核验。无法读取额度时按更小工作块同步，不能假设能精确预知中断。

顺序：更新本人成员记忆与新增交接（集成人更新公共记忆）→ 审核待提交文件 → 显式暂存 → 提交 → 推送本人分支 → 核对 `git rev-parse HEAD` 与 `git ls-remote origin refs/heads/<当前分支>`。二者一致才算上传成功，不等合并 main 才备份。无变更时也需核验已有提交是否在远端。存在远端新提交时先整合，不强推覆盖。

失败时保留本地提交并记录错误，继续处理不依赖上传的工作，及时说明待推送状态；下次先补推。远端是公共仓库；用户本次已明确要求将 F 题原件和原始附件入库，具体清单和 LFS 获取流程见 DATA_INDEX.md。未来新增资料仍核对来源和授权，不默认扩大共享范围。
