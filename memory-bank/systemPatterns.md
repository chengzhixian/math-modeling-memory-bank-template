# 建模与协作约定

## 信息来源与状态

- 官方题面、数据说明和赛事规则是题意与提交要求的依据；`projectbrief.md` 记录经核对的摘要。
- `activeContext.md` 只放当前状态、阻碍和近期待办；`progress.md` 管里程碑；实验细节放 `experiments/`；长期有效的方法约定写在本文件。
- 将事实、假设、试验结果和最终结论分开。未验证的分析不得进入论文结论。

## 数据与代码

- `data/raw/` 保留原样；清洗代码放 `src/`，可再生中间文件放 `data/processed/`。
- 使用相对路径；记录输入数据版本、字段含义、单位、缺失值处理和异常值规则。
- 每个模型说明公式、适用条件、参数来源和评价指标。随机过程固定种子并记录运行环境。
- 图表的脚本、数据和导出文件应能互相对应；关键数值需要核对计算结果与论文表述。

## 实验与论文

- 在 `experiments/` 记录任务编号、日期、负责人、代码版本或提交号、运行命令、输入、参数、指标、结果路径和局限。
- 比较方案时使用一致的数据划分和指标；按题目需要检查敏感性、稳健性与边界情况。
- 论文中的事实、公式和外部材料标明来源。不要捏造引用；外部资料记录链接或书目信息及访问日期。

## 并行与交接

- 尽量一个任务一个分支，任务编号写在记录中；共享文件发生冲突时整合内容，不直接覆盖他人的进展。
- 任务结束更新 `activeContext.md` 和 `progress.md`。只有证据可核对时才将任务标为完成。
- 若决定改变技术栈、目录、评价方法或数据规则，在这里写明决定及原因，并同步 `techContext.md`（若适用）。
